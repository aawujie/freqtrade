## 🎯 为什么要分离配置文件？

### 问题场景

**传统方式的痛点**：
```
❌ 所有配置都在一个文件里
❌ API密钥混在代码仓库中
❌ 切换策略需要修改配置
❌ 团队协作容易冲突
```

**分离后的优势**：
```
✅ 敏感信息独立管理（不提交Git）
✅ 通用配置可复用
✅ 不同策略灵活组合
✅ 配置更清晰、易维护
```

## 🔧 两种配置包含方法

### 方法一：命令行参数（灵活）

使用多个 `-c` 或 `--config` 参数指定配置文件：

```bash
freqtrade trade -c config_base.json -c config_secrets.json
```

**特点**：
- ✅ 灵活，随时组合不同配置
- ✅ 适合临时测试
- ✅ 命令行清晰可见
- ⚠️ 命令较长，容易出错

### 方法二：配置文件内引用（推荐）

在主配置文件中使用 `add_config_files` 参数：

```json
{
    "add_config_files": [
        "config_base.json",
        "config_secrets.json"
    ],
    "strategy": "MyStrategy"
}
```

**特点**：
- ✅ 配置关系明确
- ✅ 命令行简洁
- ✅ 适合固定配置组合
- ✅ **推荐用于生产环境**

## 📁 推荐的配置文件结构

```
user_data/
├── config_base.json              # 基础通用配置
├── config_secrets.json           # 敏感信息（不提交Git）
├── config_pairs_spot.json        # 现货交易对
├── config_pairs_futures.json     # 合约交易对
├── config_composed.json          # 组合配置
└── strategies/
    ├── DoubleMAStrategy.py
    └── ichiV1.py
```

### 各配置文件职责

| 配置文件 | 职责 | 是否提交Git |
|---------|------|------------|
| `config_base.json` | 通用交易参数 | ✅ 是 |
| `config_secrets.json` | API密钥、Token | ❌ 否 |
| `config_pairs_spot.json` | 现货交易对列表 | ✅ 是 |
| `config_pairs_futures.json` | 合约交易对列表 | ✅ 是 |
| `config_composed.json` | 组合其他配置 | ✅ 是 |

## 🎯 实战示例

### 场景1：现货双均线策略

```bash

    -c user_data/config_base.json \
    -c user_data/config_secrets.json \
    -c user_data/config_pairs_spot.json \

{
    "add_config_files": [

    "timeframe": "1h",
    "db_url": "sqlite:///trades_double_ma_spot.sqlite",
    "logfile": "logs/double_ma_spot.log"

```

使用：
```bash
freqtrade trade -c user_data/config_double_ma_spot.json
```

## 🔄 配置文件优先级规则

### 覆盖规则

**原则**：后面的配置会覆盖前面的同名参数

```bash
freqtrade trade -c A.json -c B.json -c C.json
```

优先级：`C.json` > `B.json` > `A.json`

### 示例说明

**A.json**:
```json
{
    "max_open_trades": 5,
    "stake_amount": 100
}
```

**B.json**:
```json
{
    "stake_amount": 200,
    "timeframe": "1h"
}
```

**最终生效配置**:
```json
{
    "max_open_trades": 5,     // 来自 A.json
    "stake_amount": 200,      // B.json 覆盖了 A.json
    "timeframe": "1h"         // 来自 B.json
}
```

### 嵌套对象的合并

对于嵌套对象（如 `exchange`），会进行**深度合并**：

**A.json**:
```json
{
    "exchange": {
        "name": "binance",
        "key": "xxx",
        "pair_whitelist": ["BTC/USDT"]
    }
}
```

**B.json**:
```json
{
    "exchange": {
        "pair_whitelist": ["ETH/USDT", "SOL/USDT"]
    }
}
```

**最终生效**:
```json
{
    "exchange": {
        "name": "binance",           // 保留 A.json
        "key": "xxx",                // 保留 A.json
        "pair_whitelist": [          // B.json 完全覆盖
            "ETH/USDT",
            "SOL/USDT"
        ]
    }
}
```

## 💡 最佳实践

### 1. 敏感信息分离

**✅ 推荐做法**：
```bash
# .gitignore 添加
user_data/config_secrets.json
```

`config_secrets.json`:
```json
{
    "exchange": {
        "key": "${FREQTRADE__EXCHANGE__KEY}",
        "secret": "${FREQTRADE__EXCHANGE__SECRET}"
    },
    "telegram": {
        "token": "${FREQTRADE__TELEGRAM__TOKEN}",
        "chat_id": "${FREQTRADE__TELEGRAM__CHAT_ID}"
    }
}
```

同时创建示例文件 `config_secrets.json.example`:
```json
{
    "_comment": "复制此文件为 config_secrets.json 并填入真实密钥",
    "exchange": {
        "key": "your_api_key_here",
        "secret": "your_api_secret_here"
    },
    "telegram": {
        "token": "your_telegram_token",
        "chat_id": "your_chat_id"
    }
}
```

### 2. 按功能模块分离

```
config_base.json          → 通用参数
config_secrets.json       → API密钥
config_pairs_*.json       → 交易对列表
config_risk_*.json        → 风控参数
config_notification.json  → 通知设置
```

### 3. 使用环境变量

在配置文件中引用环境变量：
```json
{
    "exchange": {
        "key": "${FREQTRADE__EXCHANGE__KEY}",
        "secret": "${FREQTRADE__EXCHANGE__SECRET}"
    }
}
```

设置环境变量：
```bash
export FREQTRADE__EXCHANGE__KEY="your_api_key"
export FREQTRADE__EXCHANGE__SECRET="your_api_secret"
```

### 4. 版本控制策略

**提交到Git**：
- ✅ 基础配置模板
- ✅ 示例配置文件（.example）
- ✅ 不含敏感信息的配置

**不提交到Git**：
- ❌ 包含API密钥的配置
- ❌ 包含真实密码的配置
- ❌ 个人定制配置

### 5. 配置文件命名规范

建议的命名规范：
```
config_<用途>_<环境>.json

示例：
config_base.json                # 基础配置
config_double_ma_spot.json      # 策略_交易模式
config_ichi_futures_prod.json   # 策略_交易模式_环境
config_secrets.json             # 敏感信息
config_pairs_spot.json          # 功能_类型
```

## 📝 完整工作流示例

### 步骤1：创建基础配置文件

```bash
# 通用配置
user_data/config_base.json

# 敏感信息（从示例复制）
cp user_data/config_secrets.json.example user_data/config_secrets.json
# 编辑填入真实密钥
```

### 步骤2：创建策略专用配置

```json
// user_data/config_my_strategy.json
{
    "add_config_files": [
        "config_base.json",
        "config_secrets.json",
        "config_pairs_spot.json"
    ],
    "strategy": "MyStrategy",
    "timeframe": "1h",
    "db_url": "sqlite:///trades_my_strategy.sqlite"
}
```

### 步骤3：运行

```bash
# 实盘交易
freqtrade trade -c user_data/config_my_strategy.json

# 回测
freqtrade backtesting -c user_data/config_my_strategy.json

# Hyperopt优化
freqtrade hyperopt -c user_data/config_my_strategy.json
```

## 🎓 学习要点总结

1. **两种方法**：命令行 `-c` 参数 vs 配置文件 `add_config_files`
2. **优先级**：后面的配置覆盖前面的配置
3. **安全第一**：敏感信息单独文件，不提交Git
4. **模块化**：按功能分离配置，提高复用性
5. **环境变量**：使用 `${VAR}` 引用环境变量
