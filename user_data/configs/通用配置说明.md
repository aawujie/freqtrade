# 📦 通用配置模块说明

## 🎯 设计原则

**configs/ 目录是通用配置模块库，所有策略都可以复用这些配置。**

### ✅ 正确做法
- 配置模块通用化，适用于所有策略
- 在策略配置中引用通用模块
- 通过**覆盖参数**实现策略特定配置
- 模块职责单一，易于维护

### ❌ 错误做法
- ~~为每个策略创建单独的配置模块~~
- ~~在 configs/ 中存放策略特定配置~~
- ~~重复定义相同的配置项~~

## 📁 通用配置模块清单（11个）

### ⚙️ 基础配置模块

#### 1. config_base.json
**用途**: 通用交易参数（所有策略共用）

**包含内容**:
- 基础交易参数 (max_open_trades, stake_amount, etc.)
- 订单定价配置 (entry_pricing, exit_pricing)
- 订单超时设置 (unfilledtimeout)
- Pairlists 配置
- 内部参数 (internals)

**使用方式**:
```json
"add_config_files": ["configs/config_base.json"]
```

**覆盖示例**:
```json
// 在策略配置中覆盖特定参数
{
  "add_config_files": ["configs/config_base.json"],
  "max_open_trades": 5,        // 覆盖默认值
  "stake_amount": 20            // 覆盖默认值
}
```

---

#### 2. config_secrets.json
**用途**: 敏感信息（API密钥等）

**包含内容**:
- Exchange API 密钥
- 敏感配置使用环境变量

**安全措施**:
- ✅ 已添加到 `.gitignore`
- ✅ 使用环境变量保护敏感信息
- ✅ 提供 `.example` 文件作为模板

---

### 📊 交易对配置模块

#### 3. config_pairs_spot.json
**用途**: 现货通用交易对配置

**包含内容**:
- trading_mode: "spot"
- 默认主流币种白名单（12个）
- 通用黑名单（杠杆代币等）

**使用方式**:
```json
// 使用默认交易对
"add_config_files": ["configs/config_pairs_spot.json"]

// 覆盖交易对
{
  "add_config_files": ["configs/config_pairs_spot.json"],
  "exchange": {
    "pair_whitelist": ["BTC/USDT", "ETH/USDT"]
  }
}

// 追加黑名单
{
  "add_config_files": ["configs/config_pairs_spot.json"],
  "exchange": {
    "pair_blacklist": ["SHIB/USDT", "PEPE/USDT"]
  }
}
```

---

#### 4. config_pairs_futures.json
**用途**: 合约通用交易对配置

**包含内容**:
- trading_mode: "futures"
- margin_mode: "isolated"
- 默认主流币种白名单（10个）
- 通用黑名单（杠杆代币等）

**使用方式**:
```json
// 使用默认交易对
"add_config_files": ["configs/config_pairs_futures.json"]

// 覆盖交易对（策略特定）
{
  "add_config_files": ["configs/config_pairs_futures.json"],
  "exchange": {
    "pair_whitelist": [
      "BTC/USDT:USDT",
      "ETH/USDT:USDT",
      "ASTER/USDT:USDT"  // 添加特殊币种
    ]
  }
}
```

### 📢 通知配置模块

#### 5. config_telegram.json
**用途**: Telegram 通知配置（通用）

**包含内容**:
- 完整的 Telegram 消息模板
- 所有事件类型（启动、买入、卖出、警告等）
- 使用环境变量保护 token

**使用方式**:
```json
// 启用 Telegram
"add_config_files": ["configs/config_telegram.json"]

// 禁用 Telegram（覆盖）
{
  "add_config_files": ["configs/config_telegram.json"],
  "telegram": { "enabled": false }
}
```

---

#### 6. config_webhook.json
**用途**: Webhook 通知配置（通用）

**包含内容**:
- 完整的 Webhook 消息模板
- 支持企业微信、钉钉、飞书
- 所有交易事件通知
- 保护触发通知

**使用方式**:
```json
// 启用 Webhook
"add_config_files": ["configs/config_webhook.json"]

// 覆盖消息格式
{
  "add_config_files": ["configs/config_webhook.json"],
  "webhook": {
    "entry": {
      "content": { "text": "自定义买入消息：{pair}" }
    }
  }
}

// 禁用 Webhook
{
  "add_config_files": ["configs/config_webhook.json"],
  "webhook": { "enabled": false }
}
```

### 🌐 API 服务配置模块

#### 7. config_api_server.json
**用途**: API Server / Web UI 配置（通用）

**包含内容**:
- API Server 基础配置
- 默认端口：8080
- 安全认证配置（使用环境变量）

**使用方式**:
```json
// 使用默认端口 8080
"add_config_files": ["configs/config_api_server.json"]

// 多策略运行，覆盖端口
{
  "add_config_files": ["configs/config_api_server.json"],
  "api_server": {
    "listen_port": 8081  // 策略 A 使用 8081
  }
}

{
  "add_config_files": ["configs/config_api_server.json"],
  "api_server": {
    "listen_port": 8082  // 策略 B 使用 8082
  }
}
```

## 🔄 配置覆盖机制

### Freqtrade 配置合并规则

1. **按顺序加载配置文件**
   ```json
   "add_config_files": [
     "configs/config_base.json",      // 第 1 层
     "configs/config_secrets.json",   // 第 2 层
     "configs/config_pairs_spot.json" // 第 3 层
   ]
   ```

2. **后面的配置覆盖前面的**
   - 同名参数：后面的覆盖前面的
   - 嵌套对象：深度合并
   - 数组：完全替换（不合并）

3. **主配置文件最后加载**
   - 主配置文件中的参数优先级最高
   - 可以覆盖任何模块中的配置

---

### 覆盖示例

#### 情况 1: 简单参数覆盖
```json
// config_base.json
{
  "max_open_trades": 3,
  "stake_amount": 100
}

// 策略配置
{
  "add_config_files": ["configs/config_base.json"],
  "max_open_trades": 5  // 覆盖为 5
}

// 最终结果
{
  "max_open_trades": 5,     // ✅ 已覆盖
  "stake_amount": 100       // ✅ 保持不变
}
```

---

#### 情况 2: 嵌套对象合并
```json
// config_pairs_futures.json
{
  "exchange": {
    "name": "binance",
    "pair_whitelist": ["BTC/USDT:USDT", "ETH/USDT:USDT"]
  }
}

// 策略配置
{
  "add_config_files": ["configs/config_pairs_futures.json"],
  "exchange": {
    "pair_whitelist": ["DOGE/USDT:USDT"]  // 覆盖白名单
  }
}

// 最终结果
{
  "exchange": {
    "name": "binance",                    // ✅ 保持不变
    "pair_whitelist": ["DOGE/USDT:USDT"]  // ✅ 已覆盖（数组完全替换）
  }
}
```

---

#### 情况 3: 数组完全替换
```json
// config_pairs_futures.json
{
  "exchange": {
    "pair_whitelist": [
      "BTC/USDT:USDT",
      "ETH/USDT:USDT",
      "BNB/USDT:USDT"
    ]
  }
}

// 策略配置
{
  "exchange": {
    "pair_whitelist": ["DOGE/USDT:USDT"]
  }
}

// 最终结果（注意：不是追加，是替换）
{
  "exchange": {
    "pair_whitelist": ["DOGE/USDT:USDT"]  // ⚠️ 完全替换，BTC/ETH/BNB 都没了
  }
}
```

## 💡 最佳实践

### 1. 配置模块化原则

✅ **DO（推荐）**:
```
configs/
├── config_base.json           # 通用基础配置
├── config_pairs_spot.json     # 通用现货交易对
└── config_webhook.json        # 通用 Webhook
```

❌ **DON'T（不推荐）**:
```
configs/
├── config_base_ichiV1.json       # ❌ 策略特定
├── config_pairs_doubleMA.json    # ❌ 策略特定
└── config_webhook_strategy1.json # ❌ 策略特定
```

---

### 2. 参数覆盖原则

✅ **在策略配置中覆盖**:
```json
// config_ichiV1_modular.json
{
  "add_config_files": [
    "configs/config_base.json",
    "configs/config_pairs_futures.json"
  ],
  
  "_override": "在这里覆盖特定参数",
  "max_open_trades": 5,           // ✅ 覆盖通用配置
  "exchange": {
    "pair_whitelist": [            // ✅ 覆盖交易对
      "BTC/USDT:USDT",
      "ASTER/USDT:USDT"
    ]
  }
}
```

❌ **不要修改通用配置模块**:
```json
// ❌ 不要为了一个策略修改 config_pairs_futures.json
```

---

### 3. 环境变量使用原则

✅ **敏感信息使用环境变量**:
```json
{
  "webhook": {
    "url": "${FREQTRADE__WEBHOOK__URL}"
  },
  "api_server": {
    "username": "${FREQTRADE__API_SERVER__USERNAME}",
    "password": "${FREQTRADE__API_SERVER__PASSWORD}"
  }
}
```

✅ **设置环境变量**:
```bash
export FREQTRADE__WEBHOOK__URL='https://your-webhook-url'
export FREQTRADE__API_SERVER__USERNAME='admin'
export FREQTRADE__API_SERVER__PASSWORD='strong_password'
```

---

### 4. 多策略运行原则

**场景**: 同时运行多个策略

✅ **正确做法**:
```json
// config_strategy_A.json
{
  "add_config_files": ["configs/config_api_server.json"],
  "strategy": "StrategyA",
  "api_server": { "listen_port": 8080 }  // ✅ 覆盖端口
}

// config_strategy_B.json
{
  "add_config_files": ["configs/config_api_server.json"],
  "strategy": "StrategyB",
  "api_server": { "listen_port": 8081 }  // ✅ 覆盖端口
}
```

## 🎯 总结

### 核心理念
1. **configs/ = 通用模块库**
2. **策略配置 = 引用模块 + 覆盖参数**
3. **不为每个策略创建单独模块**
4. **通过覆盖机制实现定制化**

### 优势
- ✅ 配置复用，减少重复
- ✅ 统一管理，易于维护
- ✅ 灵活组合，适应不同场景
- ✅ 清晰结构，便于理解

### 使用流程
1. 在策略配置中引用需要的通用模块
2. 在策略配置中覆盖需要定制的参数
3. 不修改通用模块，保持其通用性
4. 需要时添加新的通用模块，而非策略特定模块
